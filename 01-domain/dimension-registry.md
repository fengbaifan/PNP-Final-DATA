# Dimension Registry — 维度体系成长注册表

本文件定义当前垂直领域的 Level 2 维度注册规则。它不把 5 个维度固定为永久结构，而是把它们视为当前知识积累阶段的稳定核心维度集。

## 一、设计原则

1. **当前稳定，不代表永久固定**：5 个维度通过 2026-07-16 的 1,285 KU 重评，不是系统上限；实时 KU 数量以 health 快照为准。
2. **维度从知识中涌现**：新增维度必须来自无法归类的知识元、跨维度主题或反复出现的研究问题。
3. **先 Topic、再 Theme、后 Dimension**：具体问题能作为既有 Theme 下的 Topic 时不新增 Theme；能作为 Level 3 Theme 表达时不新增 Level 2。
4. **维度必须有组织能力**：一个 Level 2 维度至少能稳定组织 2 个 Level 3 Theme，每个 Theme 继续组织可操作 Topic。
5. **演化必须可追溯**：新增、拆分、合并、弃用维度都必须保留旧编号与迁移说明。

## 三、维度生命周期

| 状态 | 含义 | 允许操作 |
|---|---|---|
| `core` | 稳定核心维度 | 正常承载 Theme、Topic 与知识元 |
| `proposed` | 候选维度 | 记录观察，不修改正式 hierarchy |
| `pilot` | 试运行维度 | 可建立临时映射和样本 Theme/Topic |
| `core_candidate` | 准备晋升 | 需通过 evolve-hierarchy、sys-audit、evidence/boundary/hierarchy impact 审查 |
| `split_candidate` | 准备拆分 | 需定义拆分边界和迁移影响 |
| `merge_candidate` | 准备合并 | 需说明重叠原因与旧编号映射 |
| `deprecated` | 不再扩展 | 保留历史链接，不再新增 Theme/Topic |

## 四、新维度候选条件

候选维度必须同时满足：

1. 至少 5 个知识元无法自然归入现有维度，或至少 2 个成熟 Theme 长期横跨多个维度且无法被现有维度解释。
2. 该候选不是新增 Topic 或 Theme 即可解决的问题。
3. 候选维度有独立核心问题，且与既有维度互不重叠。
4. 至少能组织 2 个 Level 3 Theme。
5. 每个候选 Theme 至少包含可操作 Topic，并具备理论、实证与文献支撑。
6. 有完整迁移计划：编号、链接、主题归属、索引、历史版本。
