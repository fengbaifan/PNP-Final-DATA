# read-full

## 触发边界

仅在以下情况执行：

- 用户明确要求完整阅读或遗漏审查；
- ingest coverage ledger、manifest 或候选召回显示缺口；
- 历史来源缺少可审查的覆盖证明；
- 高风险来源需要独立复核。

不按每日、每月或固定 ingest 次数触发，也不默认串接在每次 ingest 后。

## 执行

1. 解析并确认唯一来源路径；路径不明确时停止，不猜测目标。
2. 扫描标题、图注、脚注、参考文献和其他结构边界，建立文档地图。
3. 使用适合当前读取工具和上下文的自适应分段完整阅读正文，记录已覆盖 span；不得只靠正则或实体扫描替代阅读。
4. 将来源内容与现有 KU、claim、relation、structure 和 ingest 候选对照。
5. 区分已有覆盖、别名、低价值提及、实质遗漏和无法判断项。
6. 输出报告；新发现只形成 ingest/discovery 候选，不直接创建或修改知识事实。

## 输出

- 输入路径、总 span 与实际已读 span；
- 文档结构和特殊元素摘要；
- 已覆盖、可能遗漏、需要证据和无法判断的对象；
- 与 ingest coverage 的差异及建议下一跳。

报告默认进入当前 work package；只有用户要求持久化时才写入 `05-outputs/drafts/<doc-id>/`。

## 边界

- 只读 `02-sources/` 和知识库，不直接写回 KU、claim、relation 或 hierarchy。
- 同一 Agent 的复读是补充审查，不冒充独立语义验收。
- 机械实体召回和覆盖率只能提供候选信号，不能证明语义完整。
- 不写或压缩全局日志，不创建固定周期任务。
