# enrich

负责阶段 5，围绕可用知识元的明确缺口补足。

## 输入与工作

读 KU、对齐结果与本次缺口，判断缺少的是定义、身份边界、语境、事实还是出处。以来源内容为核心，按 REV-017 查阅 Wikipedia、Wikidata，并按对象和缺口选择 Getty 或其他官方来源（博物馆、档案馆、图书馆、机构及出版社等）。Getty 按适用范围使用 ULAN、TGN、AAT 或 CONA，不要求每个实体遍历全部数据库。
每个实体的 Wikipedia—Wikidata 双重身份验证遵循 verify；已完成的结果复用，未完成的逐项处理并留状态。其他官方来源可以支持明确事实，但不能冒称已满足这一配对要求。章内回读、同书书目与索引核对属于来源内补漏，不等于本阶段的外部补足完成。
阅读外部实际正文/记录，只补与理解本书对象及关系有关的内容，不堆积链接、扩写完整百科或填满模板；记录采用内容、准确出处和实际访问日期。书目记录只能支持书目事实，不等于读过被引文献原件。
采用内容准确表述，区分原文、外部补充和自身解释；标题与描述按 ingest 字段及正文规则保持中英文对应，修改一侧时同步另一侧，不扩大事实或验证范围。同一条证据判断不重复审核。新来源/新对象超出本次范围时只记线索，后续回 ingest，不自动扩张任务。

## 产出、状态与交接

过程在 03-processing/<task-id>/process/knowledge.md，结果在 04-knowledge/results/<task-id>.md，正文原位更新。记录补了什么、来源、未解决项及阻断性。
按 ingest 正文参考逐项审视对象所属类型的内容范围。人物名称/生平/亲缘/履历/作品/评价/研究文献、作品属性与建筑沿革等适用缺口应明确记录；不能仅因现有摘要可读就判断无须补足。单值属性用字段，重复项目和历史变化用有出处的列表/表格；历史名称、所有权、收藏位置不以当前值覆盖旧值。核实信息才能写入，未查、资料未载、争议与不适用分开。
身份配对已完成且无实际内容缺口时，可记已审查无新增；查过但未找到证据记问题未解决，不能记补足完成。双重验证未完成的对象保留原文支持状态及其有证据的关系，不把这一缺口变成删除依据；身份冲突或关键关系依据仍缺失时阻断对应合并/关系，其他可用内容带限制交 relate。
新增证据影响身份/验证判断时回 verify，涉及机器状态写回才调用其受控接口。知识增长不自动触发 synthesize。
