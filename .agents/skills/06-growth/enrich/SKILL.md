# enrich

---

## enrich 流程

```
1. 读取04-knowledge/units/<type>/<名称>.md，识别缺失字段
2. 先读取知识元中已有的外部链接与验证状态，再补充检索新的开放网页来源
3. 对实际网页正文做语义分析，判断应补哪些定义、边界、特征、历史语境与关键链接
4. 分析页面底部参考文献/书目，筛选最核心来源作为补足与后续扩展线索
5. 按类型补足正文、参考文献与链接
6. 如涉及验证状态提升，转入 verify 两阶段工作流
```

## enrich 核心原则

1. enrich 的核心不是“确认链接存在”，而是基于网页可读内容补足知识元语义。
2. Wikipedia / Wikidata / 其他网页链接首先是导航锚点与来源落点，不是 enrich 的完成标准。
3. 对字段较少、正文稀薄、定义模糊的知识元，应优先补写语义内容，而不是继续堆叠链接。
4. enrich 必须阅读网页正文后再决定写回内容；禁止只根据搜索结果标题、摘要或 QID 做表面补写。
5. enrich 写回应使用压缩后的中文语义重述，禁止把网页原句大段粘贴进知识元正文。
6. 若页面只支持部分事实或边界仍不清楚，必须诚实保留不确定性，不得把推测写成确定事实。
7. 遇到 Wikipedia 页面时，应默认检查页面底部 references / bibliography / further reading，而不是只读取正文主体。

## 来源策略

1. term 优先使用定义原典、权威参考书、学术出版物或专业机构页面；Wikipedia/Wikidata 主要用于导航、身份与术语消歧，不能替代学术语义来源。
2. Person / Work / Publication / Institution / Event / Place 可优先使用原始记录、馆藏/机构页面、学术出版物、Wikipedia/Wikidata 及其他可公开访问、可回溯、可阅读的来源。
3. Google Scholar、Perplexity 或搜索结果页只是发现渠道，不是最终 evidence；写回时必须落到可阅读、能直接支持目标事实的具体来源。
4. 来源网站不以当前示例列表为上限；只要来源能直接支持目标事实、可稳定访问、可被人工复核，即可纳入 enrich。
5. enrich 不得只记录“查过某网站”；必须记录实际使用的来源链接；Wikipedia/Wikidata 只有在确实存在且被使用时才写入，不设强制配额。
6. enrich 必须读取这些链接中的实际内容来补足知识元，而不是只把 URL 当作装饰性附录。

## 语义补写判断

enrich 应根据页面语义自行判断补写重点，但默认优先考虑以下信息：

1. 定义与对象边界：它是什么、不是什么、是否常被与邻近概念混用。
2. 核心特征与类型学：组成要素、常见子类型、编码方式、方法差异。
3. 历史脉络：提出者、形成时期、扩散路径、代表案例。
4. 使用场景与局限：适用于什么、不适用于什么、常见误读或方法风险。
5. 相邻概念区分：与相似术语、相关方法、上位概念的差异。
6. 页面底部参考文献：哪些书、论文、目录或权威出版物最能支撑该知识元，并可作为后续扩展线索。

当知识元字段较少时，优先补 `描述`、`definition`、`characteristics`、`contents`、`critiques`、`历史意义`、`概念边界` 等能提升语义可读性的内容，而不是机械新增低价值字段。

## Wikipedia 参考文献分析

当 enrich 使用 Wikipedia 页面时，除正文外还应检查页面底部的 `References`、`Bibliography`、`Further reading`、`Sources` 等部分，并执行以下判断：

1. 区分“支撑页面撰写的零散脚注”与“对该对象真正重要的核心文献”。
2. 优先选择学术专著、权威论文、关键目录、当事人著作、代表性馆藏出版物等高信号来源。
3. 不要机械搬运长串引用；通常只选择最能定义对象、建立历史脉络或代表研究传统的少量核心文献。
4. 若页面底部文献明显优于当前知识元已有参考文献，应将其补入知识元 `## 参考文献`，并在适当时补进 `sources`、`key_publications` 或正文相关段落。
5. 这些文献不仅是当前 enrich 的支撑来源，也可作为后续扩展、建 relation、补 publication/person/work 的候选线索。
6. 但 Wikipedia 页面列出某文献，不等于该文献自动成为核心文献；仍需根据对象相关性、学术权威性、被引地位和解释价值做人类判断。

### 核心文献筛选启发

- 优先原典、奠基研究、标准传记、代表性专著、权威馆藏/出版社条目。
- 优先直接讨论该知识元本体的文献，而不是只在大综述中顺带提及它的材料。
- 若对象是术语或方法，优先定义性、历史性、方法论性文献。
- 若对象是人物或作品，优先标准传记、catalogue raisonne、馆藏目录、作者自述与权威研究。
- 若对象是事件或机构，优先官方档案、历史研究和高质量学术综述。

## 链接写回规则

1. 已存在 `## 验证状态` 区块时，优先沿用现有写法补入 `权威来源URL`、`来源URL`、`Wikidata URL` 等链接字段。
2. 若知识元已有 Wikipedia / Wikidata 链接，enrich 应先读取这些链接对应内容，再决定还缺什么。
3. 若某一知识元没有独立 Wikipedia 页面，但存在可用 Wikidata 项或其他权威网页，必须诚实记录“直接页面缺失”与实际采用的替代链接。
4. 链接写回不等于验证完成；涉及 `evidence_status`、`verification_level`、`last_verified`、正文验证结论时，仍必须走 verify。

## 类型补足重点

| 类型 | enrich 优先补足内容 |
|---|---|
| person | 身份锚点、职业/领域、时期、关键作品、合作与影响边界、核心传记/研究文献、Wikipedia/Wikidata 链接 |
| term | 定义、核心特征、概念边界、类型区分、历史脉络、局限/误区、代表作品/人物、关键方法论文献、Wikipedia/Wikidata 链接 |
| work | 创作者、年代、媒介、语境、作品分析（主题/风格/图像志）、当前收藏/出版信息、关键目录/研究文献、Wikipedia/Wikidata 或馆藏页链接 |
| publication | 作者/编者、出版信息、版本信息、学术定位、议题范围、历史语境、相关核心研究、Wikipedia/Wikidata/馆藏或书目页链接 |
| institution/place/event | 身份事实、时间地点锚点、功能角色、历史语境、相关作品/人物、关键历史研究或档案来源、Wikipedia/Wikidata 链接 |

## enrich 与 verify 的边界

- enrich 负责：发现缺口、读取外部网页、分析正文与页面底部参考文献、筛选核心来源并补正文、补参考文献、补可追溯链接。
- verify 负责：collect evidence JSONL、apply 验证结果、提升验证状态。
- enrich 产出的 Wikipedia/Wikidata/开放网页链接可作为 verify 的导航锚点与候选证据入口，但不能绕过 verify 的两阶段写回。

## 最小完成标准

一次 enrich 不应只新增链接。至少应满足以下之一：

- 明确补足了定义、边界、特征、历史意义等正文语义；
- 清理了残留原文、过薄描述或错误概括；
- 为字段明显稀薄的知识元补入了能支持后续阅读和 verify 的关键内容。
