# compose

按用户任务查询、组织和呈现可用知识；不自动启动发现或替页面补造数据。

## 输入与工作

1. 明确问题、受众、范围及交付形式，读有效知识、关系/发现结果与限制。普通查询交付有依据的回答即可。
2. 先组织文稿与内容结构，区分来源事实、解释与未决项；记录选择理由，不另作重复知识裁决。
3. 页面任务保留现有样式、布局和适用交互，形成内容定稿后绑定新数据。accepted.yml 指定当前有效输入，统计、类型筛选、层级、节点详情与关系均由实际数据生成。
4. 没有新数据时显示空状态，结构未形成时不显示假分组；旧项目数字、预设 A–E 和旧文案不能充当本项目成果。页面向下导航不改变知识自下而上的生成方向。

## 产出与完成

过程在 05-outputs/process/<output-id>.md；当前定稿、成果链接和限制在 results/<output-id>.md。页面沿用 knowledge-graph.html，内容只引用知识与证据原位置，避免多份当前主页面。
按任务核对内容忠实性、统计、空状态、筛选、节点详情、来源链接与交互；发现错误回责任阶段。页面不是独立证据，输出回流只在有实际问题/新线索时进行。
输出登记记录使用依据和真实状态；metadata 和生成器按实际使用需要，不因普通问答创建空输出包。
