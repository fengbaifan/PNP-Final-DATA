# 分阶段工作流

本文件从属于 AGENTS.md，定义能力和交接。实际状态以各任务 results 为准：当前已执行第一章样例的第一部分，第六章后置，第二部分暂停；来源及遗留文件的存在不算研究成果。

## 第一部分：知识元与知识图谱

| 阶段 | 输入 | 工作 | 产出与交接 |
|---|---|---|---|
| 1 摄入 | 用户指定材料、来源版本和范围 | 核对资产、可读性、来源定位与缺失项 | 来源登记、可处理范围及缺失清单；可读且范围明确的材料交处理 |
| 2 处理 | 确定范围的正文、注释及必要图像 | 完整语义阅读，理解论述、语境、对象、断言和歧义 | 可追溯的语义分析与覆盖依据、候选线索；上下文充分的对象交成稿，未读或有关键歧义的对象单列 |
| 3 知识元 | 分析依据和对象候选 | 判断对象边界和类型、检索已有对象，以统一元数据、类型内容、关系与证据三部分成稿；内容含双语描述与结构化信息 | 新增/更新/暂缓清单及 KU 草稿，标明属性缺口及证据范围；实际写入后登记有效对象，成稿不等于已对齐 |
| 4 对齐 | KU 草稿及待核问题 | 初步核对同名、别名、身份、版本和明显冲突，依 verify 尝试 Wikipedia—Wikidata 双重身份核对 | 身份边界可用即可带缺口进入补足，不要求详细资料齐全；分开记录章内对齐、双重验证及冲突，关键身份不明对象不合并 |
| 5 补足 | 对齐结果及明确内容缺口 | 依 enrich 用 Wikipedia、Wikidata、Getty 及适用官方来源补足；复用已核身份，区分原文与外部补充 | 具体补充及依据、双重验证状态、剩余缺口和阻断性；来源内补漏不冒称外部补足完成，可用内容带限制交关系 |
| 6 关系 | 可用 KU 与原文/断言证据 | 分析端点、类型、方向、时间和语境 | 正式/待证/否决关系及依据；形成当前图谱，无正式关系也可形成真实结果 |

ingest 负责阶段 1–3，verify、enrich、relate 分别负责阶段 4–6。先保存本阶段过程与结果再交接；并非每阶段另建工作包或申请用户批准。

按 REV-032，当前第一章按“摄入与处理 → 知识元登记 → 对齐 → 补足 → 关系”依次收口。每步先保存唯一当前定稿，再清理重复、过时的过程叙述和已被替代的中间工件，然后交接下一步；不同时推进多个尚未收口的阶段，也不把已有下游文件当作本轮定稿。定稿沿固定路径更迭，不另复制“最终版”。必要分析、来源定位、未决项及改变结论的裁决须保留；可恢复的旧工件在核对 Git 记录及依赖后退役，并清理其派生入口。来源本体、用户原话及不可替代证据不删。

## 第二部分：知识发现与知识呈现

用户明确启动后，synthesize 根据指定范围的 KU、关系与断言证据分析；不要求整个语料库全部处理或全部外部验证。纳入对象的证据范围和不确定性须清楚，关键依赖不成立时先回补。

| 环节 | 语义工作 | 产出与成立依据 |
|---|---|---|
| KU/关系 → Topic | 比较对象及联系，识别共同呈现的具体问题、模式和差异 | Topic 的问题表述、成员、关系与证据、边界和反例；不能只把同名标签放在一起 |
| Topic → Theme | 分析 Topic 之间的支持、差异和张力 | 主题及其成员 Topic，说明共同问题和新增的组织/解释意义 |
| Theme → Dimension | 识别主题之间形成的分析视角 | 维度及其主题、视角边界、与其他维度的交叉和差别 |
| Dimension → Domain | 分析维度如何组成较完整的问题体系 | 领域及其维度、核心问题与边界；项目名和书名不直接充当发现结果 |
| 成果组织 → 页面 | compose 组织可用内容、确定设计与定稿、绑定真实数据 | 当前成果和页面、证据链接及内容/交互检查；保留样式，不继承旧数字或预设结构 |

四层涌现均由 synthesize 承担，不增加四套技能或审批链。各层具体名称、数量和归属事先不设定；候选、成立和暂缓分别记录。有证据形成多少层就保存多少层，不能为了完整树凑节点。允许交叉归属、拆分、合并和反证，成员稳定 ID 不依赖上层编码。展示可以从 Domain 向下导航，但生成机制自下而上。

## 过程、结果与成果位置

| 工作 | 过程 | 当前结果与成果 |
|---|---|---|
| 摄入、处理 | 03-processing/<task-id>/process/stages.md，收口后只留必要裁决与清理记录 | 同包 results/stages.md 保存来源范围、逐行语义分析、定位/覆盖、校正与交接缺口的唯一当前定稿；来源资产在 02-sources |
| 知识元至关系、发现 | 03-processing/<task-id>/process/knowledge.md，按阶段分节 | 04-knowledge/results/<task-id>.md 链接 units、quality、structure 的唯一内容 |
| 呈现 | 05-outputs/process/<output-id>.md | results/<output-id>.md 及唯一页面/导出文件 |
| 系统调整 | 06-runtime/governance/system-upgrade-log.md 的过程部分 | 同一日志结果部分，不新增报告副本 |

source_id 标识来源版本，KU 路径标识知识对象，task-id 标识此次工作范围；一个任务可以引用多个来源和对象。不要以单章编号限制跨来源发现，也不按阶段复制 KU。
读取与接续先看当前 results 的范围、状态和未决项，再定位相关 process 段落与证据；每阶段只写实际发生的过程，更新对应结果后交接，不为每条消息新建工作包或在所有目录复制总结。纯系统调整只更新规则、需求索引和系统日志，不写成业务阶段完成。
人工交接以 results 为准，机器执行结果仅存必要执行事实并被引用。仍在使用的 compact-v4 包按原接口保留证据；按上述收口规则确认被替代的旧包可退役，不为保留旧格式维持重复结果。普通语义任务不强制五件套，调用该格式的工具时才遵守对应机器协议。

## 交接、状态与回退

过程说明做了什么及判断理由；结果说明范围、输入版本、成果位置、当前状态、未解决项，以及哪些对象可交给下一环节。
状态使用未开始、处理中、已完成、部分完成、受阻、暂不开展。完成审查但仍缺证时写明“审查已结束、问题未解决”；不把它写成补足完成或事实已确认。候选和批量执行状态只在实际使用时记录，不另加审核轮次。

- 来源、阅读或语境不足：回摄入/处理；原声明范围不得为通过检查任意缩小。
- 身份/版本/冲突问题：回 verify；具体缺口：回 enrich。
- 关系依据不足：回 relate 或其必要上游；不让弱关联混入正式图谱。
- 发现不能被下层支持：暂缓、修订或撤回对应结构，不倒推原文事实。
- 页面暴露错误：回责任阶段，页面只能呈现已知状态。
- 输入或结论变动：标记受影响下游待复核，只重做相关依赖；已接受且未受影响对象不重复处理。

正式事实至少可追溯，必要检查可融入工作；批量机器写回才启用独立计划、dry-run 和恢复日志。inspector 按问题检查，system-upgrade 维护规则，不成为每阶段必走的新流程。
