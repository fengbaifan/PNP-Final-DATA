# 论文写作建议

本目录是论文定位、写作建议与投稿选择的固定入口，依据REV-075、REV-076建立，更新于2026-09-14。后续在原文件迭代，不按日期复制建议。它是研究写作支持目录，不是知识处理的第七阶段。

- 本文件：论文类型判断、写作框架及方法／实验建议。
- [投稿期刊与分区依据](journal-targets.md)：SCI／SSCI方向、候选期刊、分区年份和来源。
- [第一章当前结果](../04-knowledge/results/patrons-and-painters-chp-1.md)：业务完成状态的唯一入口。本目录的评估快照不能替代它。

## 推荐定位

**优先写“艺术史知识图谱构建方法与案例研究”：以可追溯的语义构建方法为主线，以领域知识图谱为成果，以对照实验和可用性验证支撑。**

“方法”“实验”“数据集”“知识图谱”并非四种互斥选项：方法是拟提出的贡献，实验是检验贡献的证据，数据集是可复用产物，知识图谱是知识组织形式。当前可以形成论文框架和方法稿，但还不宜将已有工程结果直接写成已验证的完整研究论文。

| 方向 | 当前适合程度 | 应怎样写／还缺什么 |
|---|---|---|
| 领域知识图谱构建与应用方法 | 最适合，建议主线 | 围绕艺术史文本中的对象边界、跨句关系、事实来源及外部补足，提出可复现构建方法，并通过有限案例和实验评价 |
| 通用新算法／模型方法 | 当前依据不足 | 尚没有已证明的新抽取算法、训练方法或一般性性能改进；使用LLM、AGENTS和Skills本身不构成算法创新 |
| 实验／比较研究 | 适合作为主论文核心章节 | 需要明确研究问题、公平对照和真实结果；目前没有执行完的对照实验，不能仅汇总节点和测试数量 |
| 数据集／资源论文 | 后续可选 | 需固定发布范围、稳定标识、机器可读数据、数据说明、质量证据及实际复用方式；当前1,019个KU的数量不是自动达标或不达标的门槛 |
| 艺术史知识发现论文 | 当前不开展 | 需要实际历史问题与发现证据；知识涌现暂停，不以自动聚类或网页截图补出研究结论 |

知识图谱论文无需一律采用RDF或新建数据库；现有存储可以保留。若选择强调Linked Data的期刊和文章类型，则应在成稿阶段按其要求，从唯一知识元生成相应标准化导出，而非维护第二套手工事实库。知识图谱的表示、构建、质量与应用属于不同研究环节，可参照[Hogan等的综述](https://aidanhogan.com/docs/knowledge-graphs-computing-surveys.pdf)。

## 拟写的核心问题与贡献

建议研究问题是：**如何把艺术史学术文本中的实体、历史语境和关系转化为可查询知识图谱，同时保留每条事实的出处与适用范围，并约束外部补足的扩张？**

可以组织为三个待验证贡献，不提前称为已经证明的创新：

1. **语境明确的对象建模。** 区分城市与政体、建筑与机构、作品与委托、原作与版本；同一人物的多种角色作为有据属性，避免按单一身份硬分类。
2. **可追溯的分阶段构建。** 六阶段传递实体提及、字段、关系候选及证据；书内陈述与外部补足逐条区分，初步身份对齐与事实验证分别记录。
3. **有限扩展与关系完整性。** 已采纳事实涉及独立具名对象时建立或复用必要端点，只沿有据事实补齐创作、赞助、亲缘、隶属、安置等关系；不递归摄入所有外部网页链接。

这些是本项目可能形成贡献的具体位置。“证据追溯”“分阶段”本身已有广泛研究，后续相关工作比较必须说明本项目新增了哪些规则、表示或实证认识，不能仅换一个领域就宣称方法首创。AGENTS和Skills宜作为执行协议及复现材料，论文正文按研究问题解释方法，不按仓库文件逐个介绍。

暂定题目：

> 面向艺术史学术文本的证据可追溯知识图谱构建：以《赞助人与画家》为例  
> Evidence-Traceable Knowledge Graph Construction from Art-Historical Scholarship: A Case Study of *Patrons and Painters*

若最终只验证第一章，摘要和数据部分明确限定第一章；题目也可进一步限定。实际尚未证明时，不用“高准确率”“完整”“通用”“自动知识发现”等效果词。

## 建议正文结构

| 章节 | 写作任务 |
|---|---|
| 引言 | 提出对象歧义、跨句关系、来源混合的实际问题，说明为什么普通实体清单不足以支持研究查询 |
| 相关工作 | 比较文化遗产知识图谱、文档级关系抽取、证据与来源建模；围绕具体差异写，避免堆叠工具介绍 |
| 材料与知识表示 | 交代原书章节、外部记录、实体与关系边界、三部分卡片及证据粒度；书内事实与扩展事实分口径 |
| 构建方法 | 定义六阶段输入、语义操作、输出及回送条件；说明模型、提示词、版本和实际介入方式 |
| 实验设计 | 给出问题、对照、评价对象、分母及限制；未执行的设计不写成结果 |
| 结果与错误分析 | 分别报告结构、追溯、参照匹配、稳定性、成本和查询情况，分析对象混淆与关系遗漏实例 |
| 讨论与结论 | 解释单章局限、外部来源依赖和未进行人工校验的影响，界定可复用贡献 |

优先完成当前实体与证据缺口，再固定实验输入和协议。第一章已用于规则开发，不能将同一章反复修订后的结果称为未见测试；第六章仍后置，本轮不启动。若以后增加第六章，应先冻结规则，并报告跨章重复实体及来源重叠。

不进行人工校验可以继续当前构建研究，但会限制“语义正确性”和“完整召回”的证据力度；不要求为了论文恢复人工标注，也不保证任何期刊一定接受这种证据范围。过程中的用户修订必须如实披露，不能把“本轮不新增人工校验”写成“整个项目从未有人介入”。

## 关系分析前移的修订方案（REV-077）

状态：2026-09-14已按REV-079实施。保留六阶段交付顺序，关系线索从处理阶段开始记录和交接；未新增阶段、审核轮次或中央关系候选库。实际规则见[pipeline](../.agents/pipeline.md)，第一章候选见[处理定稿](../03-processing/patrons-and-painters-chp-1/results/stages.md#三原书关系候选指代与证据跨度rev-079)，裁决见[过程记录](../03-processing/patrons-and-painters-chp-1/process/knowledge.md#rev-079关系候选回溯与正式关系集中裁决2026-09-14)。

### 问题定位

现行pipeline的处理阶段已要求理解对象、断言和歧义；第一章处理定稿也已有句意摘要及对象／断言线索。缺口不是完全没有前期关系分析，而是没有明确约定“原文提及—关系候选—端点映射—最终裁决”的持续引用。末阶段若主要依赖已经补足的卡片重新找关系，书内陈述与外部事实容易混淆。

### 六阶段分别增加什么

| 阶段 | 拟明确的工作与交接 |
|---|---|
| 摄入 | 固定来源版本与章页／行号基准，保留原件及OCR之间的区别 |
| 处理 | 完整语义阅读时记录关系候选、原文提及、跨句／跨页指代及支持跨度，保留发言者、否定、推测、引述和适用范围；此时不要求KU或外部标识齐全 |
| 知识元 | 将候选中的原文提及映射到新建或已有KU，保留原词及原位置；无法确认的端点保持待定，不根据关系猜造实体 |
| 对齐 | 核定提及对应哪个人物、对象或版本，更新端点映射；身份确认不自动确认关系，也不将外部消歧依据说成原书已具名 |
| 补足 | 复用书内候选以定位具体缺口；记录外部来源实际支持的字段或关系。外部新关系另留来源，不覆盖书内候选；外部发现必需端点按已有规则回送 |
| 关系 | 逐项处理书内候选与已采纳的外部关系事实，核定端点、类型、方向和限定；裁决为正式、待证或否决，并保留对应依据。继续反查卡内事实，避免候选记录本身的遗漏被掩盖 |

处理时出现关系候选不等于同时开展正式关系阶段，也不改变用户要求的分阶段成果收口。

### 最少需要保存的候选信息

候选是03中的语义分析记录，不是新增KU类别，也不直接进入frontmatter.relations。可采用短表或条目，沿用已有稳定跨度编号；同一跨度有多项关系时增加局部序号。仅实际存在候选时记录，不对每行强填空表。

| 信息组 | 记录内容 |
|---|---|
| 候选定位 | 任务内稳定引用或锚点，关联原有语义跨度；编号不随最终KU改名而重排 |
| 原文提及与指代 | 原文中的名称／代词及各自位置；代词可能指向的前项与判定依据，尚有歧义则保留多个候选 |
| 关系表述 | 忠实转述原文动作及参与角色；暂定方向，不因当前词表缺少名称而丢弃关系 |
| 原文证据 | 来源版本、章、印刷页、行号和实际原句／既有原句引用；支持跨度可不连续，分别列出跨页正文及脚注，不把其间无关内容统当证据 |
| 必要语境 | 按实际语义保存时间、版本、发言者及否定／推测／转述等限定；泛称惯例不直接套到具名人物 |
| 后续去向 | 端点KU映射、明确缺口和最终裁决入口；当阶段尚未执行时不预填确认结果 |

原书候选的唯一当前记录放在现有`03-processing/<task-id>/results/stages.md`的相应语义跨度下；处理判断的改变理由留在`process/stages.md`。后续端点映射、外部候选及关系裁决在已有`process/knowledge.md`相应阶段引用这些候选，不复制原句和整套候选表。正式事实仍只在04的现行关系记录维护。索引或裁决表只保存引用与状态，不形成第二套正式关系。

### 防止外部知识混入原书的具体规则

1. **原书原句与最初判断可追溯。** OCR修订须有原件依据；后续纠正解释时保留改变理由。不能用外部页面改写原句，也不把当前的事后解释回填为最初阅读结论。
2. **身份依据与关系依据分开。** 外部材料可能说明“这位画家”是谁，但不能因此证明他与某人的赞助、师承或合作关系。正式关系必须有实际支持该谓词的证据。
3. **书内事实与外部事实按证据分别归源。** 同一实体或同一关系可以同时有书内和外部证据，逐条标明各自支持范围；不强制整张卡或整条边二选一归类，也不为不同来源复制同一事实边。
4. **外部确认不能取消原书限定。** 原书说“可能”“据某人回忆”或否认某关系时，该陈述原样保留；外部材料提出确定事实或反证，另记其来源与冲突，不能把原书改成确定陈述。
5. **正式关系可追溯到具体出处。** 最终边链接实际支持它的来源或证据绑定；过程候选ID用于追踪判断，不能单独代替事实证据。具体机器字段是否需要调整，应在实施时按现行关系契约核对，方案阶段不另造协议。

示意例（非书中引文、不是待写入事实）：“A委托这位画家绘制祭坛画。他随后将其安置于某教堂。”处理时应分别记录委托与安置两个候选，结合前文判断“这位画家”“他”“其”各指什么。外部资料即使显示B有一件作品现藏该教堂，也不能直接证明B就是原文画家、这件实物就是委托对象，或现藏等于原定安置。

### 第一章的具体执行顺序（REV-078）

以下保留实施步骤，作为方法复现说明。REV-079已按该步骤完成全章事后回溯；它不冒称最初处理已经做到。

**第一步：补齐规则，固定本轮输入。** 按下节所列位置修改pipeline及相关Skill；共同记录约定只维护一处，各Skill说明本阶段如何使用。记录来源版本、OCR行号基准和本轮业务输入版本，保留已有实体及历史判断，不另建整库副本。本轮范围是第一章原书关系追溯，不扩张外部采集。

**第二步：先完成原书关系候选的回溯补建。** 读取[第一章OCR](../02-sources/02-Markdown/01_CHP-1.md)，以[处理定稿](../03-processing/patrons-and-painters-chp-1/results/stages.md)中的80个语义跨度作导航，从原文L1到L980逐段回读。实际分析单位为完整句群：遇断行、跨页和脚注先接清语境，必要时对照原扫描页，不把80个跨度当作互不相干的固定切块。

每段先判断原文说了什么、谁在说、关系涉及谁、限定是什么；关系不明确时记录候选和疑点，不猜端点。把实际候选按上文最小格式写入处理定稿的对应跨度下，保存候选锚点与原句定位；无候选的跨度保留简短处置，不造空候选。改变旧解释的理由只记process/stages.md。本步先形成全章当前候选结果再交接，不同时重写正式关系。

以下为具体记录示例，候选编号仅作格式示意，尚未在业务文件登记：

| 项目 | 依据L295–307的拟记录 |
|---|---|
| 候选 | `ch1-r-example`：Guercino受要求为西西里一所修道院绘制祭坛画 |
| 位置与原句 | 第一章p.9，L295–296；保留原句及行间断词，不用摘要代替原句 |
| 参与对象 | Guercino；受委托祭坛画；未具名修道院。原文此处没有给出可直接采用的委托人姓名 |
| 指代 | L301的“he”与L306的“He”指Guercino；L306的“the picture”指本段拟制祭坛画，不能据此锁定现存版本 |
| 语境 | 1665是该委托及询问的叙述时间；本段不证明作品完成年，也不证明已经安置 |
| 候选拆分 | 受要求绘制、询问图像细节、询问拟悬挂与光线分别理解；“询问如何悬挂”不产生已安置关系 |
| 后续 | 参考现有Guercino、相关委托作品和询问事件卡判断是否复用；未知修道院不借用外部同名机构填上 |

**第三步：将候选映射到已有对象，再核对已有关系。** 在[知识过程记录](../03-processing/patrons-and-painters-chp-1/process/knowledge.md)现有阶段下，用候选锚点引用第二步结果，依次记录端点KU映射和裁决去向。检索accepted对象，人物、委托、实物、机构与建筑分别判断；仅缺少必要端点才回知识元阶段。身份问题回对齐，具体事实缺证才做定向补足；每次回送只处理相关对象。

对照关系时，逐项核对“端点＋谓词＋方向＋时间／版本／角色”，不能只按两个名称相同认定匹配。处理四种情况：书内候选已有正确边则复用；有书内依据而缺边则补建；原有边仅有外部依据则保留正确外部归源；端点或证据冲突则修正、暂缓或否决并保留裁决。无证边不因历史已存在而自动保留，也不因原书未提及就删除有外部实证的边。

注意现行`relation_source: explicit`的定义是Agent已在KU声明，**不能拿它判定“原书明确记载”**。书内／外部归属应从具体evidence_ref或claim证据绑定及sources的支持范围判断；若现行接口不能完整表达多条证据，实施时先核对兼容方式，不擅自改这个枚举的含义或把所有关系按卡的主来源归类。

**写回与本轮交付。** 完成上述核定后，只更新受影响的KU关系、证据引用及必要字段，并按现有工具生成相应可读关系与索引；不手工维护第二份正式图谱。对发生变化的端点、类型、方向、限定和引用做针对性检查；批量写回才采用现行dry-run／apply接口。

交付继续沿用三个既有文件：

| 文件 | 本轮新增结果 |
|---|---|
| 03的results/stages.md | 原文各跨度的回查状态、关系候选、指代与证据定位；它只声明处理范围完成，不声明全部史实已验证 |
| 03的process/knowledge.md | 候选→端点映射→关系裁决的可追踪入口，外部事实的证据范围以及改变旧判断的理由 |
| 04的第一章results | 原书候选总数及正式／待证／否决去向，本轮新增／修正／复用关系，剩余端点与证据缺口；外部关系另说明来源口径 |

每个书内候选应有明确去向，每条被纳入本轮审查的正式关系应有具体可定位证据；待证可以作为真实交付结果保留。候选数量、行号覆盖及机械检查不证明召回完整或语义准确。全章回查属于模型的原文语义工作，不新增人工标注或独立验收；知识发现、第六章和页面继续暂停。

### 总体判断与论文定位

当前适合作为“证据可追溯的艺术史知识库构建方法与案例研究”的原型。六阶段有合理分工，来源—事实—关系具备追溯基础；尚不足以支持“高准确率、完整提取、方法优于基线或广泛泛化”的结论。流程设计、技术实现、知识资源和实验有效性是不同贡献，不能用Skill数量、Git提交、节点数量或机械测试互相替代。不开展知识发现不妨碍研究知识库构建；不进行新增人工校验则须限定语义质量论断。

### 流程与方法

1. 保留摄入→处理→知识元→初步对齐→补足→关系的交付顺序，但处理阶段即保存实体提及、共指、关系候选及证据跨度；最后阶段完成身份明确后的正式关系。避免在补足前丢失原书关系，或将补足知识反写成书内陈述。跨句综合具有合理的方法依据，参见[DocRED](https://aclanthology.org/P19-1074/)，但该数据集不验证本项目的实际效果。
2. “逐行阅读”是覆盖责任，语义判断单位应为完整句群及其跨页／脚注依赖。980行、80个处理跨度和534段摘录只能说明声明范围与记录，不是完整召回的分母。
3. 九类可作本领域应用词表。person/family等具体对象、term概念、procedure惯例及event具体事件应明确层次与同一性规则。机构／建筑、委托／实物、原作／复制品的区分是可检验的方法点；不必为论文引入庞大预设本体。
4. “以语义分析为主、少脚本”是实施选择。论文需固定可复现的模型标识、提示词及规则快照、输入上下文组织、来源版本、采纳／暂缓规则、重试与停止条件；可记录的参数与不可恢复的历史配置如实区分。不将当前配置补写为历史执行配置。
5. 身份配对只验证对象指向；字段及关系分别绑定事实证据。Wikipedia/Wikidata共同引用或转引Haskell时不能按网站数计独立互证。区分原书作者判断、所引证言、外部陈述与模型解释。来源—处理活动—责任主体的表达可参照[W3C PROV-O](https://www.w3.org/TR/prov-o/)，无需复制第二套数据。
